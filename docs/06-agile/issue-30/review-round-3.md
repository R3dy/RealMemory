## Residual observations (NON-BLOCKING — recorded for the architect/orchestrator, not approval conditions)

**R1 — handler-recorded `lands=0` is later overwritten by idle's `-1` on hosts without system-content persistence.** Two writers share the `hook_lands:experimental.chat.system.transform` key with a latest-wins read: the transform handler (`recordLandsOutcome(...,0)` on push-assertion failure) and `checkSentinelLanded` (records -1 on a no-system-role transcript, always later in the session). On the real 1.18.17 host the assertion-failure path is dormant (the existing `pendingInjection` push to the same array demonstrably works), so this is reachable only on a hypothetical host whose `output.system` array silently drops a push AND persists no system content. The `0` row is preserved in the store, so a future read-rule refinement (e.g. "any recent 0 wins over -1") needs no migration. Below the FAIL bar: exotic trigger, exit code unchanged (0 either way), and the UNVERIFIABLE notice already directs manual verification.

**R2 — the exit-2 evidence test is stated as "any metric/memory row" (§4.3, twice) but "store has memories" (A30.2 criterion).** Under the §4.3 reading, a session that fires only `session.created` (zero user turns) would satisfy "evidence of real sessions" while `chat.message`/transform/idle sit at zero fires → a false DEGRADED on a healthy install — the class 2-C2 attacked. Materiality is low: 0 of 1,731 sessions on the live host have zero user messages, so the divergence is latent on realistic data, and either reading passes the A30.2 test as written. Recommend (not require) the architect tighten the evidence test to memory rows (the sharp #28 signature: MCP-written memories exist while always-fire hooks are silent) during build, or log it to PARKING_LOT for Phase 1.
